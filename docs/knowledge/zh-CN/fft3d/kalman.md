# FFT3D Kalman 状态与随机访问

[目录](../README.md)

bt=0 在每个空间块、每个频点上递推，而不是做有限时间窗的 FFT。输出 0 不做 Kalman 处理，除 AVS 显式 mode=1 的未初始化平面外复制源数据；虚拟状态 S0 直接初始化，不先变换源帧 0。之后 S_n 表示已经消费源帧 n 的状态。

## 一次递推

L 是复数估计，C 是协方差，Q 是过程协方差。X 是当前源帧经中心化和分析窗后的空间 FFT，递推前不做 degrid。均匀模型 R=R0；曲线或采样使用 R=max(P,1e−15)。正 pfactor 的大小不缩放 Kalman 采样表，sigma 仍用于初始化 C/Q。

```text
R0 = sigma_eff^2 / (1/(bw*bh))
S0: L=0+0i, C=Q=R0
motion = (X.re-L.re)^2 > R*kratio^2
      or (X.im-L.im)^2 > R*kratio^2
if uniform R==0:
    L=X; C=Q=0
elif motion:
    L=X; C=Q=R
else:
    sum = C+Q
    gain = sum/(sum+R)
    Q_new = (gain*gain)*R
    C_new = (1-gain)*sum
    L_new = gain*X+(1-gain)*L
```


运动判定分别比较实、虚部平方差；任一超限同时重置两部分，等号仍平滑。不是将复数模平方与阈值比较。上式按 binary32 的指定顺序计算；增强、逆变换、量化的结果不反馈到状态。

## 两步算例

R0=R=2、kratio=2、X1=1+0i。阈值为 8，差平方为 1，走平滑：sum=4,gain=2/3，所以 L1=2/3，C1=4/3，Q1=8/9。

第二步取 X2=1+0i，仍不触发运动。sum=20/9,gain=10/19，因此 L2=16/19，C2=20/19，Q2=200/361。若第一步 X1 改为 3+0i，则 9>8，直接 L1=3,C1=Q1=2。实际 float 保留规定舍入，不用分数化简式替代实现。

C 的实/虚逻辑分量始终相等，Q 也如此，所以每个 bin 实际只存复数 L 和两个独立 float C/Q，共 16 字节，而不是六个 float 的 24 字节。C 与 Q 不相等，不能把它们继续合并。

## 乱序请求怎样恢复

设 W=kalman_warmup，默认 8，earliest=max(0,n-W-1)。n>0 请求开始时固定最大的已完成检查点 j∈[earliest,n]，恢复私有副本；没有合格检查点则令虚拟 j=earliest，初始化 L=0、C=Q=R0。顺序消费 j+1..n，最多 W+1 次递推。精确命中 j=n 时仍取源帧 n 的属性和复制区域。帧 0 不推进也不重置现有状态。

n=10000、W=8 时：冷启动消费 9992..10000；检查点 9996 只需 9997..10000；9991 在预算边界内，9990 已太旧。W=0 的冷启动仅处理当前帧，但有 n-1 检查点时仍能延续长期历史。倒序请求不能借用未来检查点；缓存淘汰不会触发隐式全前缀回放。

输出时复制 L_n 为私有频谱，做可选增强、逆 FFT、合成和裁剪。ROI/场打包属于实例配置；不同实例状态不共享。

## 预算与代价

默认缓存上限为 `max(64 MiB,一个完整检查点实际容量加元数据)`，最多四个检查点，LRU 淘汰。大于 64 MiB 的完整状态仍可保留一个；它不是固定 64 MiB 硬上限，也不受 cache_mb/cache_frames 控制。

1280×720 YUV420、32×32 块、16 像素重叠、三个平面的状态 payload 约 47.265 MiB；展开六分量表示约 70.897 MiB。活跃请求的私有状态、起点快照、变换工作区及宿主缓存另占内存，被请求持有的淘汰快照也可继续存活。

固定 W 时，冷启动递推工作量不随绝对帧号增长。采样模型可能先读取窗口外 pframe，并在递推时再次获取，所以 W+1 不保证总取帧回调数或墙钟时间。分阶段释放约束源帧持有量，宿主元数据与上游缓存仍不在插件内存保证内。失败不发布检查点。

## 历史依赖与并发

只在目标输出成功后发布状态，不缓存每个预热中间帧。请求使用不可变快照的私有副本，不等待另一个输出。并发冷请求可能重复计算并选择不同历史；同一帧先发布的状态在缓存保留期间获胜，但另一在途请求仍返回自己的计算结果。淘汰后重算可能走另一段历史并改变输出。这是对原有无上限规范回放的明确取舍，不再保证请求顺序无关。

连续处理通常每帧只推进一步，保留长期状态；预热量是补算预算，不是滚动历史长度。更长预热可能改善启动，但不保证迅速恢复长期降噪。运动重置按频点发生，不是场景边界检测。参数定义见 [FFT3D API](../../../api/zh-CN/fft3d.md)。
